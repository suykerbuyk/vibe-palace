# vibe-palace v10.2.0 — release notes

Released 2026-10-09. Covers the 153 commits in `v8.2.0..main` (tagged `v10.2.0`).

| Axis | v8.2.0 | v10.2.0 |
|---|---|---|
| MCP surface (`MCPSurfaceVersion`) | 8 | **10** |
| Data format (`RequiredDataFormat`) | 2 | 2 (unchanged) |
| MCP tools | 81 | 80 |

The tag follows the release-tag scheme in
[ADR-011](../adr/011-open-task-header-schema-and-format-axis.md),
`v<MCPSurfaceVersion>.<RequiredDataFormat>.<build>`
(`internal/surface/version.go:34-41`, `internal/surface/format.go:77`). Derive
the numbers from source rather than from this page:
`grep -n 'const MCPSurfaceVersion' internal/surface/version.go`,
`grep -n 'const RequiredDataFormat' internal/surface/format.go` and
`jq '.surface_version,(.tools|length)' internal/mcp/tool_surface.golden.json`.
`vp check --check release-version` compares the running binary's tag against both
constants and fails a tag that is ahead of or behind them
(`internal/check/release_version.go:52`).

## One tag, two epics

This single release ships everything since v8.2.0, and it carries two epics'
worth of user-visible contract changes:

- **(A) Authored-only vault, host-local search index** — ADR-014. The vault stops
  holding derived search data; each host now compiles its own search index from
  the vault's authored artifacts. This was planned as "surface 9 / v9.2.0".
- **(B) Supported project rename and vault lifecycle** — `vp vault rename`,
  `vp vault copy --as`, and the retirement of the one-shot project-slug engine
  and the split/merge MCP tools. This bumped the surface to 10.

A single tag, **v10.2.0** (surface 10, data format 2), covers both. The data
format is unchanged, so nothing already on disk needs rewriting
(`internal/surface/format.go:20-25`); ADR-014 decision 5's new `origin` field is
additive and read by a plain `json.Unmarshal`.

Why this works: see
[ADR-014](../adr/014-search-index-compiled-per-host-from-vault-artifacts.md) and
[ADR-013](../adr/013-vault-project-lifecycle-and-departure-records.md). This page
lists what changed and does not repeat either document.

## Epic (A): the vault holds authored artifacts; each host compiles its own index

Before this release, capture wrote every transcript chunk and every extracted
knowledge-graph triple into tracked files under `palace/`, and git carried all of
it. ADR-014 reverses that: the vault holds authored, immutable artifacts (session
notes with their `decisions:` frontmatter, `iterations.md`, tasks, learnings,
transcript archives, authored KG facts), and the search index is a **per-host
build** compiled from them, living under the already-ignored
`palace/.local/index/`.

The migration to this layout — the **authored-only-palace** migration — is a
single revertible commit per vault, run by the operator, not by this release.
Installing v10.2.0 does not migrate any vault. What this release does is make
every binary ready for that migration and gate out any older binary that could
undo it.

### Contract changes (ADR-014 decision 10)

Each item below is a user-visible behaviour change. ADR line references are to
[ADR-014](../adr/014-search-index-compiled-per-host-from-vault-artifacts.md).

1. **A search of a truly empty project is now an error, not an empty success.**
   A project with no session notes, no iterations, no tracked transcript
   archives, no local chunks and (on an unmigrated vault) no tracked drawers is
   **truly empty**. Searching it now returns an error that names
   `vp index rebuild`, where it used to succeed with `{"items":[]}` and the CLI
   printed "No results found." A non-empty project with zero hits still returns
   an empty list — that answer is true. **Cross-project search** no longer fails
   as a whole when one project is empty: it **skips truly empty projects**, and a
   skipped project reads `absent` in coverage (decision 8).

2. **`filed_at` becomes the session date.** A transcript or decision chunk's
   `filed_at` is now the UTC day of the session's start, not the clock time when
   indexing ran (ADR 265-343). **Date filters therefore move**: a session
   backfilled in October but held in May is found under May, not under the day
   the backfill ran. The same holds for `as_of` and timeline order on regenerated
   temporal triples.

3. **Content without a tracked archive leaves search.** The migration removes
   every derived drawer and every extracted triple and entity line from the
   tracked tree — including the 23,632 transcript drawers (22.5 MiB) and 41,364
   extracted triples (69%) whose session has no tracked archive (ADR 49-64,
   240-264). The loss is from search, not from history: the migration tags its
   parent commit `pre-authored-only-<date>` and pushes the tag, so every dropped
   byte stays recoverable with `git show`. A session that never had an archive is
   still searchable through its note, just not through its transcript.

4. **`vp_palace_backfill_decisions` is removed.** Decision chunks are now rebuilt
   from session-note frontmatter on every index build, so the tool has nothing
   left to do (ADR 978-980). It is gone from the MCP surface.

5. **`vp_capture_session` no longer indexes its `transcript` text.** The
   `transcript` parameter now only creates an archive on a host without a hook
   (`archive_transcript`); it no longer chunks and indexes that text inline (ADR
   495-500). This is also the removal of capture-only, transcript-only search: a
   session that never gets an archive is searchable through its note alone.

6. **`vp_refresh_index` is now the MCP twin of `vp index rebuild`.** It checks
   the index run lock (through the holder record, without taking the lock) before
   it spawns; if an ingest or rebuild already holds the lock it returns a refusal.
   Otherwise it starts the rebuild as a detached process and returns at once, so
   an MCP client never times out, and progress is read through `vp_index_status`
   (ADR 739-742).

7. **New `vp index` command and a read-only status tool.** `vp index rebuild`
   and `vp index status` on the CLI, and the read-only MCP tool `vp_index_status`
   (ADR 854-855). `vp_index_status` is added to the tool surface.

8. **`index_coverage` in bootstrap**, with seven states, tested in this order,
   first match wins: `absent`, `stale`, `legacy`, `unbuilt`, `notes`, `partial`,
   `current` (ADR 857-882). `absent` now means *truly empty only*; "not built yet
   on this host" is `unbuilt`. Every state carries a reason. `vp index status`
   and `vp_index_status` report the same coverage.

9. **The baseline set, the historical backlog, and the per-host rebuild that
   clears it** (ADR 126-147, 505-531, 805-833).
   - When a host's ledger is first created, it records a **baseline set**: the
     `source_sha256` of every tracked archive present at that moment, minus the
     archive named by the trigger that created the ledger. It is a *set*, not a
     time — no clock or date is involved. Copy, merge and import add the archives
     they bring in, on the host that runs them.
   - Automatic ingest (hook, pull, hook-less capture, `vp mcp` startup) covers
     every pending archive **not in the baseline set**, newest first. An archive
     is pending when its session is absent from the ledger, or the ledger records
     a different `source_sha256` for it.
   - The archives in the set are the backlog. Automatic ingest never clears it.
     While it remains, coverage reads `partial`, and its reason names separately
     the pending archives (beyond this run's budget), the backlog, and the failed
     archives — each pointing at `vp index rebuild`.
   - **The per-host step.** Every host runs `vp index rebuild` once per vault to
     clear its backlog. The command is resumable; it exits at once, naming the
     holder (pid, kind, project, start time), if an ingest or rebuild already
     holds the run lock for that vault; and on completion it empties the baseline
     set, so coverage can reach `current`. Its locks are host-local under
     `palace/.local/locks/`, so one host's run never blocks another host.
   - **Which projects, before the quantum split.** On the personal vault, until
     the quantum projects are split into their own vault, the per-host rebuild
     leaves out both `qa-metabuild-system` and `orchestrator`. Run it as:

     ```
     vp index rebuild --all --skip qa-metabuild-system --skip orchestrator
     ```

     (`--skip <slug>` is repeatable; `cmd/vp/cmd_index_rebuild.go:23`). Those two
     projects keep their backlog and read `partial` until the post-split rebuild
     in the quantum vault. **No search of a quantum project is run before the
     split** (operator ruling 439). See the runbook, `doc/rollout/v10.2.0.md`.

10. **A per-run budget, and a skip after N failures** (ADR 524-531, 593-604).
    Each automatic run has a **per-run budget**, counted in archives (newest
    first), with a wall-clock cap as a backstop; the repair of missing vectors
    counts against it. A failure is non-fatal: a warning goes to `vp.log` and a
    failure count, keyed by the archive's `source_sha256`, to the ledger.
    Automatic runs skip an archive after N failures, and only `vp index rebuild`
    retries it. N and the budget are set by measurement.

11. **Background embedding after SessionEnd.** The SessionEnd/PreCompact hook only
    *spawns* the detached pending-archive ingester (it never embeds — the host
    kills the hook at 30 s, and embedding runs at about 46–48 s of CPU per MiB of
    archive). The ingester then embeds the new archive in the background. One
    ingest or rebuild runs per vault on a host at a time. `vp mcp` startup also
    starts the ingester as a backstop, so an archive outside the baseline set and
    within that run's budget is ingested by the next session start or pull at the
    latest (ADR 703-738).

12. **`palace-store-drawers` is skipped on a migrated vault**, and a new
    **`kg-tracked-extracted`** audit dimension reports tracked extracted records
    on a migrated vault (ADR 1215-1221). `project-tree-coherence` is rewritten,
    unconditionally, on a derived-aware presence predicate, so the migrating host
    and the pulling hosts agree.

13. **`vp_list_projects` drift gains 12 rows.** Twelve projects in the live vault
    have no `palace/<p>/.surface`; on every host that pulls the migration they
    lose their `palace/<p>/` directory, which held only derived files (ADR
    1208-1211). Each shows as a drift row.

14. **`vp audit rooms --apply`** now relabels room metadata in the host-local
    chunk store on a migrated vault and writes nothing tracked; it **refuses on an
    unmigrated vault**; and its help and output say that the next rebuild undoes a
    relabel (room curation lives in the room keywords, not in moved records; ADR
    911-921).

15. **`vp migrate mempalace` requires `--project`** naming a project the vault
    already holds (`cmd/vp/cmd_migrate.go:268`, `:312`, `:330`). Its import is
    written to that project's host-local index on this host only; it has no
    archive, so nothing can regenerate it, and the first `vp index rebuild` after
    a `chunks.fingerprint` change discards it with the rest of the project's
    chunks. The remedy is to re-run the import after that rebuild (ADR 254-263).

16. **Copy and merge need two migrated vaults.** `vp vault copy` (and its `--as`
    composition) refuses an **unmigrated destination**, and refuses an unmarked
    source into a marked destination, before any write — the two-marker refusal
    (`internal/storage/lifecycle_copy.go:680-705`). Migrate the source first, or
    create the destination with a `vp vault init` vault. See the note under epic
    (B) below: ADR-014 decision 11 still names `vp_vault_split` and
    `vp_vault_merge` as carrying this refusal, but those tools were retired in
    this release; the supported move/copy path is `vp vault copy` and
    `vp vault rename`.

17. **Surface 10 is mandatory and forward-only.** It is a breaking, mandatory,
    **forward-only** binary upgrade: every host that writes the vault runs
    v10.2.0 or later, and none goes back. A rollback restores the data, not the
    old binaries (ADR 923-927, 1256-1276). See *Upgrade notes* below.

### Also covered (ADR-014 decision 11)

- **`vp vault init` creates a vault born migrated.** A fresh vault created by
  `vp vault init` is **born migrated**: it carries the `authored_only` marker, the
  derived-path ignore lines, and an `Audits/.surface` stamp at `MCPSurfaceVersion`
  (`internal/storage/vault_init.go:191`, `initBornMigrated`; ADR 1122-1131). A
  split destination must be made this way, or migrated, first. `vp init`,
  `vp config sync` and onboarding do **not** create a born-migrated vault.
- **Split and merge leave out untracked, ignored files on a derived path**
  (`palace/<slug>/drawers/` and `palace/<slug>/ingested-archives.jsonl`), and
  never a tracked file (ADR 1224-1233). The path condition is deliberate:
  "untracked and ignored" alone would also drop the 137 untracked
  `*.manifest.json.<hash>.bak` files under `Projects/<p>/transcripts/`, and a
  purge would then delete their only copy.
- **The migration and its recovery tag.** The migration tags its parent commit
  `pre-authored-only-<date>` and pushes it; rollback is `git revert` of the
  migration commit, rehearsed on a remote-stripped copy (ADR 964-971, 1256-1276).
  On the empty-vault path (the quantum vault), the migration commit writes the
  vault's only stamp, so a revert there must re-stamp `Audits/.surface` in the
  same push.

### What changed under `palace/.local/` (not tracked)

The compiled index lives under the already-ignored `palace/.local/` and never
enters git (ADR 90-107): `index/<p>/chunks.jsonl`, `index/<p>/kg/`,
`index/<p>/ledger.jsonl` (the per-host ingest ledger, which now lives here),
`chunks.fingerprint`, `completeness.json`, `hnsw.idx`, the embed cache and the
host-local locks. The legacy tracked ledger `palace/<p>/ingested-archives.jsonl`
is deleted by a new binary once no tracked drawer remains under
`palace/<p>/drawers/`, or once the vault carries the migration marker, and the
marker-gated ignore line `palace/*/ingested-archives.jsonl` keeps it out.

### Behind the scenes (no contract change here)

- Search is now backed by one `VectorIndex` interface with a brute-force and an
  `coder/hnsw` implementation, chosen per project by chunk count (ADR decision 6).
  **HNSW is decoupled from this release** and may ship with brute force for every
  project; the HNSW children land when ready. No release version is tied to them.
- Authored knowledge-graph facts stay on `palace/<p>/kg/triples/` and
  `kg/entities.jsonl`; every record now carries an explicit `origin` field,
  `authored` or `extracted` (ADR decision 5).

## Epic (B): supported project rename and the lifecycle surface

This epic replaces the old one-shot slug migration with first-class, resumable
lifecycle commands, and retires the tooling they supersede.

### New: supported in-vault project rename

- **`vp vault rename <old> <new>`** / **`vp_vault_rename`** rename a project
  within one vault (U9), as one published commit, and move the host-local index
  store across with it. `--dry-run` prints the move set, the rewrite counts,
  every refusal, the push targets and the digest; `--expect <digest>` binds the
  plan; `--undo` reverses the host-local index step after you have git-reverted
  the rename commit (`cmd/vp/cmd_vault_rename.go`).

### New: copy a project under a new slug

- **`vp vault copy <project> --from <url> --as <newname>`** copies a single
  project from a published source vault and renames it in the receiving vault in
  one composed operation (U11): copy, then rename
  (`cmd/vp/cmd_vault_copy.go:25`). It requires exactly one project. The copy
  half's digest can be previewed; the rename runs after the copy.

### Retired: the one-shot project-slug engine and the split/merge MCP tools

- **`vp migrate project-slug --from SLUG --to SLUG` is retired** (U12). The
  supported path is now `vp vault rename`
  (`cmd/vp/cmd_migrate_project_slug_gone_test.go` pins the removal).
- **`vp_vault_split` and `vp_vault_merge` are retired** (U12). The MCP tools and
  their source are gone from the surface (`internal/mcp/tool_surface.golden.json`
  lists neither; the project-tree primitives they were built on are noted as
  retired at `internal/storage/project_tree.go:20`). The supported way to move or
  copy a project between vaults is now **`vp vault copy`**, **`vp vault copy
  --as`** and **`vp vault rename`**, together with `vp vault project delete` on
  the departing side (unchanged from v8.2.0).

> **Note for the ADR track.** ADR-014 decision 11 (lines 975-976, 1234-1252) and
> the release spec's Scope-1 item 16 still name `vp_vault_split` and
> `vp_vault_merge` as the tools that refuse an unmigrated destination. That text
> is **stale**: those tools no longer exist. The two-marker refusal now lives on
> `vp vault copy` / `vp vault copy --as` (and the same migrated-vault rule governs
> `vp vault rename`, which operates within a single vault). These notes document
> the current surface.

### Migrated-vault gating for move and copy

- **Copy refuses unless both vaults are migrated** — the two-marker refusal: a
  migrated source into a migrated destination is the only accepted pairing, and
  every other pairing is refused before any write
  (`internal/storage/lifecycle_copy.go:680-705`). An unmigrated destination is
  refused with a message pointing at `vp vault init` or running the migration on
  it; an unmarked source is refused with "migrate the source first". A marker that
  cannot be read fails closed.
- A **`vp vault init`** vault is **born migrated**, so it is a valid copy or split
  destination from the moment it is created.

## Upgrade notes

- **Every host must run the same surface.** v10.2.0 raises `MCPSurfaceVersion` to
  10. After the first v10-stamped write anywhere in the vault syncs, an older
  binary refuses every mutating command against that vault (exit 2, with the
  upgrade remediation). This is the mechanism that makes every host upgrade before
  the authored-only migration: only a surface-10 binary refuses to write extracted
  KG into the tracked tree, and an older binary's capture or `vp_refresh_index`
  would re-add it and a tidy would commit it (ADR 929-939). Install v10.2.0 on
  every host that writes to the vault (a release archive, or `make install` from
  source) and restart every AI harness on it, **before** migrating any vault or
  splitting any project. To see which writer identities the vault records, run
  `vp check --check writer-identity`.
- **Surface 10 is forward-only.** A rollback restores the data (`git revert` of
  the migration commit), not the old binaries. A reverted vault loses the migration
  marker, and a v10 binary falls back to the pre-migration rules on it: search
  reads the tracked drawers through the glide path, and capture still writes
  nothing derived into tracked paths.
- **No data migration is required to install.** The data format stays at 2, and
  nothing already on disk needs rewriting. The *authored-only* migration is a
  separate, operator-run step (`doc/rollout/v10.2.0.md`), not part of installing
  this binary.
- **`VP_SURFACE_GATE=warn`** lets a CLI write proceed past a surface-version
  mismatch, but not past a missing or unreachable vault
  (`internal/surface/gate.go`). Using it during this rollout is not recommended.

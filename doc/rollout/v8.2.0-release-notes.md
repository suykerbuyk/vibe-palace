## The headline: moving projects between vaults

This release adds commands that copy projects into another vault and delete
them from the vault they leave, and it makes vp refuse to write into a
project that has departed. How to use them is in the user guide,
[doc/VAULT-LIFECYCLE.md](../VAULT-LIFECYCLE.md). Why they work this way is in
[ADR-013](../adr/013-vault-project-lifecycle-and-departure-records.md), and
per-host vault resolution is in
[ADR-012](../adr/012-vault-resolution-precedence-and-host-project-bindings.md).
This page lists what changed and does not repeat either document.

### New CLI commands

- **`vp vault init <path> --remote <name>=<url>...`** creates a new, empty vault
  and records its remotes in the tracked `.vibe-palace/remotes.toml`. It makes
  one commit on `main` and publishes it to every remote. It is not `vp init`:
  it onboards no project and writes no host config.
- **`vp vault copy <project>... --from <remote-url>`** is run by the receiving
  vault. It copies projects from the source vault's *published* remote, never
  from a host path, in one commit carrying `Vp-Copy-*` trailers, and publishes
  that commit to every remote of the receiving vault.
- **`vp vault project delete <project>... (--moved-to <url> | --discard)`** is
  run on the vault the projects leave. It deletes them in one published commit
  that carries their departure records. With `--moved-to`, it refuses unless
  the destination's published remote holds a verified copy.
- **`vp vault clone <url> <path> [--bind <project>...]`** creates this host's
  copy of a published vault. With `--bind`, that copy becomes this host's
  primary vault for the named projects.
- **`vp config bind <slug>... --vault <path>`** binds projects to a vault on
  this host through a `[project_vaults]` table in the global config, writing
  every slug in one write. Reload the AI host afterwards, because a running MCP
  server resolved its vault at startup.
- **`vp migrate project-slug --from SLUG --to SLUG`** is a one-shot migration
  that moves all of one project's vault history to a new slug.

`copy`, `project delete` and `clone` share one flow: `--dry-run` prints a plan,
a digest and the real-run command line, and `--expect <digest>` refuses the
real run if the plan has changed. Every printed real-run and Undo line can be
pasted into a shell exactly as printed.

### New MCP tools (78 → 81 as of v8.2.0)

- `vp_config_bind`: stdio transport only. It takes `slug`, not `project`.
- `vp_vault_copy`
- `vp_vault_project_delete`: stdio transport only.

`vp_vault_split` gains an optional `departure_to` label for purge.

### Departure records and the departed-project refusal

- A project that leaves a vault gets a tracked record at
  `Audits/departures/<p>.json`. The record says whether the project was renamed
  or moved (or, via `project delete --discard`, deleted) and where it went. A
  split purge and `vp vault project delete` write these records. Split and merge
  no longer carry them into another vault.
- **The record wins over the directory.** While the record exists, every write
  into `Projects/<p>/` is refused: the MCP dispatch seam, the raw vault file
  tools, the storage writers and the commit backstop all check it. The refusal
  names where the project went. `vp init` no longer reopens a departed slug;
  only a `git revert` of the delete does.
- Only `vp vault project delete` and a `vp_vault_split` purge can write or
  remove a record. Ordinary callers cannot create, edit, move or delete
  anything under `Audits/departures/`.
- **A sync refuses to bring a departure onto a host's own work.** A pull or
  push that would bring a project's departure onto a host with unpushed or
  uncommitted work under that project now refuses, and nothing is merged
  (a61f7f6). Recovery is in
  [VAULT-LIFECYCLE.md § If a host's pull refuses](../VAULT-LIFECYCLE.md#if-a-hosts-pull-refuses).
- `vp_list_projects` reports departed projects and where they went. Bootstrap
  puts a departed project first, as a stop-class instrument.

### Resolving the vault per host

A project's vault now resolves in three tiers, in this order:

1. the checkout's `.vibe-palace.toml` `vault_path`;
2. the host's `[project_vaults].<slug>`;
3. the global `vault_path`.

Resolution fails closed on conflicting or unreadable sources. A stale binding
refuses mutating tools instead of writing into the wrong vault. `vp status`
prints the binding source. The global config template moves to schema 1.2
(`version_minor = 2`) for the new table.

## Upgrade notes

- **Every host must run the same surface.** v8.2.0 raises `MCPSurfaceVersion`
  to 8. After the first v8-stamped write anywhere in the vault syncs, an older
  binary refuses every mutating command against that vault. The reason is that
  only a v8 binary refuses writes into a departed project, and a v7 binary's raw
  file tools can forge or remove a departure record. Install v8.2.0 on every
  host that writes to the vault (a release archive, or `make install` from source) and restart every
  AI harness on it, **before** splitting any project into another vault. To see which
  writer identities the vault records, run `vp check --check writer-identity`. `VP_SURFACE_GATE=warn`
  lets a CLI write proceed past a surface-version mismatch, but not past a
  missing or unreachable vault (`internal/surface/gate.go`). Using it is not
  recommended.
- **No data migration is required.** The data format stays at 2, and nothing
  already on disk needs rewriting.
- **Each host re-embeds once.** Embed-cache directories now record an embedder
  fingerprint. Caches from before this release have none, so on first use their
  vectors are dropped and re-embedded as ordinary misses.
- **Skill shims are rewritten.** `vp commands upgrade` or `vp mcp install`
  rewrites every vp-owned persona shim with a short label. Claude skill shims
  also gain `disable-model-invocation: true`, so a persona is adopted only by
  `/vps-<name>` or a typed `vps-<name>`.

## Notable fixes and behaviour changes

- The embedder now truncates input by tokens (`[CLS]` + first
  `max_sequence_length - 2` tokens + `[SEP]`), not by characters, and clamps a
  configured length above the model's 512 positions.
- `vp tasks read` prints the body when stdin or stdout is not a terminal,
  instead of hanging in an editor. `vp tasks edit` refuses in that case.
- Every `vp migrate` command that takes `--vault` now surface-gates the vault
  that flag names.
- A split purge commits its own result as one change, so `vp vault tidy` or a
  harvest can no longer publish half a purge. It also refuses a destination
  that is not its own git repository, and a purge of a file the manifest never
  copied.
- `commit-log.anchor` now travels with its project. It names a commit in the
  project's own repository, not the vault's.
- A departed project's embed cache is removed after a pull, and cross-project
  search never serves a departed project.
- `vp vault move` refuses anything but a regular file.
- Rewriting the host config keeps its mode and symlink, and a backup is never
  written with a wider mode than the original.
- The dry runs of `vp vault tidy` and `vp vault sync` now predict the refusals
  of the real runs.
- `vp check` gains the rows `Departed caches` and `Tracked marker vault_path`.
  Its `Release version` row now checks a dev build's base tag against the
  release constants.

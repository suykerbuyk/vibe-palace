# vibe-palace v10.2.1 — release notes

Released <date>. Covers the 100 commits in `v10.2.0..main` (`git log --oneline v10.2.0..HEAD | wc -l`).

| Axis | v10.2.0 | v10.2.1 |
|---|---|---|
| MCP surface (`MCPSurfaceVersion`) | 10 | 10 (unchanged) |
| Data format (`RequiredDataFormat`) | 2 | 2 (unchanged) |
| MCP tools | 80 | **81** |

The one added tool is `vp_worktree_reconcile` (`0b8ffb1`); no tool was removed or
renamed.

The tag follows the release-tag scheme in
[ADR-011](../adr/011-open-task-header-schema-and-format-axis.md),
`v<MCPSurfaceVersion>.<RequiredDataFormat>.<build>`. Neither constant moved since
`v10.2.0`, so only the build number advances. Derive the numbers from source
rather than from this page:
`grep -n 'const MCPSurfaceVersion' internal/surface/version.go` (line 355),
`grep -n 'const RequiredDataFormat' internal/surface/format.go` (line 77) and
`jq '.surface_version,(.tools|length)' internal/mcp/tool_surface.golden.json`.
The same `jq` against `git show v10.2.0:internal/mcp/tool_surface.golden.json`
gives the v10.2.0 column. `vp check --check release-version` compares a binary's
tag against both constants. For an exact release build it fails when the tag's
major/minor axes disagree with the source constants; a development build behind its
base tag reports informational status, and a tag ahead of the constants fails
(`internal/check/release_version.go:33-47,71-84`).

Because the MCP surface-version gate remains 10, **a v10.2.0 host is not locked out
by a v10.2.1 write**: `vp_surface_check` passes on either binary. The concrete
surface is not identical: the golden file adds `vp_worktree_reconcile` and two
existing tool schema hashes also changed. That does not make mixed
binaries harmless; see the rollout section next.

## Upgrade and rollout (read this first)

### 1. Restart every `vp mcp`, and let hook-spawned `vp` finish

The killed-append recovery (`bdc37d6`) holds only once **every process that can
take a project's index commit lock runs the new binary**: every `vp mcp` server
(each AI-client session holds one), every hook-spawned `vp` (ingest, rebuild,
capture), every manually invoked `vp index rebuild`, and every detached
cold-search rebuild (locking goes through `indexstore.Lock`,
`internal/indexstore/tx.go:87-113`; cold search can launch a detached rebuild,
`internal/search/engine.go:162-175`).

After installing v10.2.1:

1. Restart every `vp mcp` server.
2. Let every in-flight `vp` process that can take the project index lock finish, or
   restart it, including hook-spawned commands, manual `vp index rebuild` commands,
   and detached cold-search rebuilds.
3. Until all such old-binary processes have exited, do not rely on the killed-append
   guarantee.

What an old binary does with the new counter file
(`palace/.local/index/.generation/<project>`, now carrying a third field `a` or
`w`; ADR-014 decision 7 and its 2026-11-18 amendment,
`doc/adr/014-search-index-compiled-per-host-from-vault-artifacts.md:754-775`;
marker handling at `internal/indexstore/generation.go:96-109,177-201`; the old
parse behaviour is at `v10.2.0:internal/indexstore/generation.go:71-80,115-128`):

- **As a reader** it cannot parse the third field and errors on the counter. The
  KG read fails and a search rebuilds, for the duration of each new writer's
  append.
- **As a writer** it resets an unparseable counter to generation 0 with a new
  epoch, forcing engines to reload; it does not delete index files. It also erases
  the marker of a dead new-binary writer, and its own commits remain unmarked, so
  killed appends from that old writer retain the previous recovery limitation.

Cost of the new binary: one extra fsynced counter write per appending commit
(about 3 ms on a virtio disk, measured in the commit's task; not re-measured for
this page) and a non-blocking lock probe per read while a marker is seen.

### 2. Claim directory: upgrade when no session is mid-flight with its cwd in a subdirectory of a project root

Session claim sentinels (`claimed-<session-id>`) now live in the `.vibe-palace/` of
the **nearest `.vibe-palace.toml` root**, not the raw cwd (`be7c460`,
`hook.ClaimDir`, `internal/hook/claim.go:57-60`; used by the hook and by
`vp_capture_session`, `internal/tools/session_tools.go:752`). Capture and the
SessionEnd hook therefore agree wherever each ran inside the project.

Upgrade when no session is mid-flight with its cwd below (inside) a project root
containing `.vibe-palace.toml`. An old claim may be nested under that cwd
(`v10.2.0:internal/tools/session_tools.go:684-686`) while the new binary looks at
the project-root claim directory, allowing one **duplicate session note** per such
in-flight session. Outside a marked project root, `ClaimDir` falls back to the raw
cwd. After the upgrade, the claim-sentinel writers described above use the
project-root `.vibe-palace` directory instead of creating claim directories under
project subdirectories.

### 3. A long-lived `vp mcp` keeps serving the OLD embedded code and skills

An MCP server's commands, personas and skills are embedded in the binary it was
started from. Installing v10.2.1 does not change a running `vp mcp`: it keeps
serving the old embedded text, including the old `chair` skill, until its AI host
is restarted. This matters for the chair changes below (`fb7721e`, `d6821e9`,
`9178395`).

### 4. Install-gated change carried in this range: tracked-marker refusal

`bc24a74` makes the resolver **refuse a git-tracked `.vibe-palace.toml` that
carries `vault_path`** (fail-closed). A host whose checkouts still carry a
committed host path will have `vp hook` capture nothing until the checkout is
cleaned to identity-only and bound in the host's `[project_vaults]` (ADR-012
Option (b)). The Tier-1 override now lives in the gitignored
`.vibe-palace/local.toml` (`2cb5621`), and `vp init --vault-path` writes it there
(`bc24a74`, `fbdd32d`).

## Changes a user could trip on

These alter behaviour you may already rely on. Each is explained in its theme
section below.

- **The transcript tier is excluded from the index by default** (`f0edf72`). A host
  that had transcript chunks in search will not get new ones; opt in per host.
- **The knowledge graph reads empty on an excluded-tier host** (`f0edf72` ->
  `eb08481`): archive-extracted entities and triples are not built. One host went
  from 5,761 entities / 6,274 triples to 0.
- **`vp index rebuild --drop-transcripts` deletes** archive-owned chunks, KG
  records and ledger rows (`eb08481`).
- **Automatic ingest skips archives over 8 MiB** (`a4d5781`; was 32 MiB). 25 of
  1,509 manifests on the measured vault (1.66%) are skipped by automatic runs and
  left to an explicit `vp index rebuild`.
- **A git-tracked marker with `vault_path` is refused** (`bc24a74`, above).
- **Under `go test`, writes to the operator's configured vault panic or error**
  (`ade62e5`, `7aeae88`, `e337ddf`). Affects people running the test suite or
  embedding the libraries in tests, not normal use.
- **The `chair` skill's review loop is bounded** (`d6821e9`): findings block a
  unit only under stated conditions, and review stops after one full pass plus one
  delta pass (a third only if the delta found a blocker).
- **`vp search` on a cold or unbuilt index returns promptly** with a
  `vp index rebuild` hint rather than building inline (`be6eca2`, `629e573`,
  `f7a3ebf`).

## User-visible changes, by theme

### Transcript tier is opt-in per host (`f0edf72`)

Transcripts were 99.3% of indexed mass (456,479 archive-owned records against
3,134 authored in the measured vault), and a full rebuild ran 7.5 to 9.6 days. The
tier is now **excluded entirely by default**, historical backlog and new sessions
alike. Archives are **still captured exactly as before**; they are simply never
ingested unless a host opts in.

- **Setting:** `[index] transcripts = false` by default
  (`internal/storage/config/template.toml:84-85`,
  `internal/storage/config/defaults.toml:49-50`), resolved per project through the existing
  config layers (`storage.ResolveTranscripts`). A project's host-local layer can opt
  that project in.
- **Flags:** `vp index rebuild --transcripts` ingests the tier on that run;
  `--no-transcripts` does not; the two are mutually exclusive
  (`cmd/vp/cmd_index_rebuild.go:29-41`).
- **Automatic runs are bounded by construction:** the cold-search launcher and the
  drain's rebuild consumer always pass `--no-transcripts`, whatever the config says.
  A source-audit rule, `automatic-rebuild-unbounded`
  (`internal/sourceaudit/automatic_rebuild_bounded.go:70-98,104-122`), fails the build if either site loses
  the flag.
- **Existing chunks are kept:** an explicit opt-in run's work survives the next
  automatic rebuild; the setting governs ingestion, not what the engine loads from
  what is already stored.
- **Cost:** measured in the commit, the authored-only cold build is 3 h 26 m against
  ~9.6 days with transcripts, and the store lands at 23,113 lines against 848,387.
  **The opt-in path is still days-long on a large vault** (`--transcripts` help text,
  `cmd/vp/cmd_index_rebuild.go:29`). Do not extrapolate those figures to another host.
- **KG consequence:** archive-extracted KG records go with the tier. See next
  section.

### Knowledge-graph honesty (`eb08481`)

An empty KG used to be served as `0` with no explanation, indistinguishable from "no
such fact". Each surface now says why, through one mapping,
`search.KGHonesty(cov, covErr, kgEmpty)` (`internal/search/kg_status.go:46`), with
additive keys `kg_status` / `kg_reason`. Statuses: `tier_excluded`, `empty`,
`unbuilt`, `absent`, `stale`, `legacy`, `coverage_unavailable`.

- Present on `vp_kg_stats` whenever the tier is excluded; on `vp_kg_query` and
  `vp_kg_timeline` only for an **empty** result; in `vp_bootstrap_context` beside
  `kg_snapshot`; and as a "knowledge graph:" line plus JSON fields in
  `vp index status`. Existing counts are never replaced.
- Authored (`vp_kg_add`) and mempalace-imported facts are not transcript-fed and
  still appear.
- `vp index rebuild --drop-transcripts` now **prints committed vs attempted counts**
  on success and on every post-rebuild error exit; exit codes are unchanged
  (`cmd/vp/cmd_index_rebuild.go:214-229`).
- Feeding the KG from authored notes instead is **not done**; it remains a deferred
  operator decision.

### Index durability: a killed writer no longer strands readers

- **Destructive commits** (`b10ebaf`): the counter file takes an optional third
  field `w`. For the whole of a destructive commit `ReadGeneration` returns the zero
  `Gen` and `ErrWriteInFlight` (`internal/indexstore/generation.go:96-109,177-201`); recovery (`generation.go:232-273`, `tx.go:132-145`)
  happens only at `Lock`, which bumps Gen with a new epoch. A reader that straddled
  a killed write can no longer install, persist or delete pre-write state.
- **Append-only commits** (`bdc37d6`): the third field gains `a` (append in
  flight), written before the commit's first write without changing gen or epoch. A
  search that finds `a` left by a dead process rebuilds and serves the append, with
  no new writer needed. A live append costs a search nothing. See *Upgrade* above
  for the mixed-binary rule.
- **Known limit** (`c905b37`): `saveGraph`'s epoch check is inert (comment
  corrected, no code change). It and the subset-graph acceptance are tracked in
  `graph-saves-carry-no-completeness-witness` (see *Known issues*).
- **Perf** (`2509bd3`): `chunks.jsonl` is folded once per commit instead of once
  per `ReplaceOwned`. The commit measured ~2.56 s per whole-file fold, 1,549 notes,
  a projected ~66 min per decision regeneration; re-measure before quoting.

### The under-test vault-write tripwire

`go test` can no longer mutate the operator's configured vault silently. Guard order
matters: each refusal is the first statement with an effect, ahead of any lock.

- `ade62e5`: seated at both write funnels (`atomicfile.writeAtomic`,
  `storage.appendUnderLock`) with an ambient-root arm.
- `7aeae88`: the six commit primitives refuse a commit to the configured vault
  under test. Seats 4-6 return `ErrAmbientVaultCommit` rather than panic, so a
  panic cannot strand a no-timeout `LOCK_EX`.
- `e337ddf`: every derived-index mutation (`indexstore` writes, `ApplyRename`,
  `RemoveRenamePending`, the embed cache) is judged by path through
  `surface.GuardTestPathWrite`, before any lock or effect.

No effect outside tests. Residuals are filed as tasks (see *Known issues*).

### Claim sentinels at the project root (`be7c460`, `ed7966b`)

See *Upgrade* item 2. In addition, `ed7966b` sweeps stale `claimed-<id>` sentinels
at session start (`hook.SweepClaims`, `internal/hook/claim.go:174-185`): a claim is
removed only when its host session is provably no longer live.

### Codex is a first-class MCP host (`749a2b8` and follow-ons)

`vp mcp install --codex` / `uninstall --codex` (`cmd/vp/cmd_mcp_install.go:56`)
register Codex through a lexical span editor over `~/.codex/config.toml`
(`internal/mcphost/codex.go:89-123`, `internal/mcphost/codex_config.go:24-27`),
never `codex mcp add` (measured to destroy per-tool approval policy). Install is
byte-idempotent and fails closed on malformed TOML. The same commit adds native
skills under `.agents/skills/` (with `allow_implicit_invocation: false`), a
SessionStart bootstrap hook (`vp codex hook session-start`) and durable transcript
capture by path (`vp codex hook session-end`).

Follow-ons in this range: `01f4885`, `1965702` (hook command and executable
resolution), `ef89e9b` (the non-capture steps the Claude hook runs), `5973097`
(note<->transcript join so Codex sessions reach the instruments), `10d0cde` (archives
dated from the transcript, turns counted), `f94cf03` (every Codex session stranded its
own transcript: the back-link guard was always true), `9f67305` (a `codex-orphans`
check reporting rollouts never archived, now a gate; `internal/check/codex_orphans.go`),
`47709dd` (Codex shim dir in the canonical gitignore set).

**Not at parity with Claude:** no `friction_score` for Codex sessions by design
(task `friction-scoring-for-codex-sessions`); parity work remains in
`codex-u4-hold-codex-to-the-host-parity-contract`.

### Cold search is bounded

- `be6eca2`: a cold, unbuilt or stale index never hangs the caller; it builds,
  serves a stale in-memory index, or fails fast with a `vp index rebuild` hint.
- `629e573`: bounds the build **preludes** (decision regeneration and the corpus
  walk) through `searchBuildCtx`.
- `f7a3ebf`: bounds the **CLI** embedder construction. The bound is `be6eca2`'s
  `readyWait`, not `629e573`'s. It is inert for a non-lazy embedder by construction
  (`Engine.EmbedderReady` returns true for anything without `Ready() bool`).
- `2509bd3`: see *Index durability*.
- ADR-016 (`2706e90`, units `71ea755`..`e30ba7a`): the index-building embed pass is
  a host-local singleton per (host, vault); automatic embed starters have an
  inter-run cooldown (`f0c04ac`).
- Search now also covers commit messages (`dcba088`): `vp_search` and
  `vp_search_cross_project` can return `commit/<sha>` hits from
  `Projects/<p>/commit-log.md`.

### Authored-only migration command, and the host-local HNSW index

Both landed after the `v10.2.0` tag (the tag is 2026-10-09 10:48; `216ea89` is
2026-10-09 19:35) and ship for the first time in v10.2.1:

- `vp migrate authored-only-palace` (`216ea89`, `cmd/vp/cmd_migrate_authored_only.go`).
  Plan-only by default, `--yes` executes, `--attest <file>` carries the operator
  attestation. The v10.2.0 release notes describe the migration as an operator step
  "not part of installing this binary"; the command itself is in this range, not in
  that tag (`git grep authored-only-palace v10.2.0 -- cmd` is empty).
- HNSW production switch (`f87bca7`, `59d272f`, `c3dc7d4`, `f423af0`, `60f1b0f`,
  `5db5b3f`): persisted graph file, per-project brute<->HNSW selection by chunk
  count, catch-up, self-heal, and a background brute->HNSW converter.

### Vault routing and lifecycle

- **MCP vault routing (ADR-012 Option C)**: a project-keyed request whose project is
  bound to a non-startup vault is served against the correct vault for reads and
  writes (`3c5c334`, `67fcda8`, `394e565`, `44bbe81`, `4e4eec4`). Single-vault hosts
  are byte-identical.
- `vp vault migrate-to <dest>` (`87315e6`): staged copy, delete and bind. A bare
  invocation is a dry-run plan.
- `vp vault gc` and quiescence-gated `.vp-locks` GC (`9b14eae`, ADR-003 amendment).
- Vault-binding: `.vibe-palace/local.toml` (`2cb5621`), tracked-marker refusal
  (`bc24a74`), cwd-aware `vp vault` git family (`fbdd32d`).

### Worktrees (`d810dce`, `7c59447`, `0b8ffb1`)

`vp worktree` now places trees under `<root>/.wt/<name>` with branch == dir name
(ADR-017). `vp worktree reconcile [--check-remote=false] [--json]`
(`cmd/vp/cmd_worktree.go:259`) is **read-only**: it classifies each worktree and
reports whether it is safe to reclaim, never deleting or fetching. It is also the
MCP tool `vp_worktree_reconcile` (read-only, `project_path` required;
`internal/tools/readonly_serve.go:169`). It is blind to an orphaned `.wt/` directory
(task `reconcile-is-blind-to-unregistered-wt-directories`).

### Chair skill (`fb7721e`, `d6821e9`, `9178395`, and earlier)

- `9178395`: the skill is split into a thin `SKILL.md` core plus
  `references/` (`internal/templates/templates/skills/chair/`). The rendered
  `vp_skill` frame is held under 17,000 bytes by
  `internal/tools/chair_skill_budget_test.go:17`.
- `d6821e9`: the review loop is bounded (see *Changes a user could trip on*) and
  unit-boundary rules are added.
- `fb7721e`: **a Chair waits on the deliverable the brief names, never on pane idle
  or a scrollback token.** Untested against a live working pane and a real project
  job pattern.
- Earlier in the range: `02bf7c1`, `26d42e9`, `5065762`, `a58b187`.

Reminder: a long-lived `vp mcp` serves the old embedded skill until its host
restarts.

### Smaller changes

- Automatic ingest cap lowered to 8 MiB (`a4d5781`, `internal/ingest/run.go:51`).
- `sourceaudit` audits one tree, not sibling worktrees (`b5a7f66`).
- `.gitignore` canonical set gains the Codex shim dir (`47709dd`).

## Known issues at release

Each is an open task; re-derive status with `vp_get_task` before quoting.

- **`graph-saves-carry-no-completeness-witness`** (planning). The witnessed load
  accepts an HNSW graph whose live IDs are a **subset** of the corpus (ADR-014
  decision 4), and no graph save records which corpus it is complete for. A debounced
  or failed save, a heal built from cached vectors, or a stale-build publish can leave
  an incomplete graph on disk that any engine consumes as current until a later
  rebuild. This is the caveat on the killed-append guarantee above. `saveGraph`'s
  epoch check is unreachable (`c905b37`).
- **`integration-cold-index-session-capture-to-search-fails`** (planning). The
  non-`-short` test `TestIntegrationSessionCaptureToSearch`
  (`internal/integration/session_pipeline_test.go:138-140`: no transcript chunk among
  the results) was last confirmed failing in a clean worktree at `c905b37`; it was
  not re-run at release HEAD `eb08481`. `make test` uses `-short` and skips it
  (`Makefile:128-132`), so a green `make test` says nothing about it. The suspected
  transcript-opt-out cause (`f0edf72`) remains unconfirmed, and the task records it
  as a design call.
- **`index-rebuild-should-throttle-cpu-and-memory`** (planning). A cold authored-only
  rebuild of the largest project saturates ~5.5 cores and **peaks at 15.0 GB RSS**
  (3 h 25 m 56 s, one measured host). A 16 GB laptop would swap or OOM. The peak is
  not yet attributed to a phase and no throttle exists.
- Residual tripwire gaps: `append-entry-paths-touch-the-vault-before-the-tripwire-fires`
  (a test appending to the configured vault creates `.vp-locks/` and a lock file
  before the tripwire panics) and `indexstore-ratchet-exemptions-are-wider-than-the-call-sites`.
- Claim store: `claim-store-diverges-across-project-roots`,
  `raw-cwd-vibe-palace-joins-outside-claims`.
- `transcript-pair-defer-is-permanent-and-blocks-push`: two orphaned `.jsonl.zst`
  files can block every vault push indefinitely.
- `model-cache-download-is-not-resumable`.
- **Not fixed, disclosed in `f0edf72`:** a coarse `Discard` on a recipe mismatch
  bypasses the preservation purge.

The added tool is `vp_archive_repair_manifest`. The CLI gains
`vp archive repair-manifest`. Derive the numbers from source
(`internal/surface/version.go`, `internal/surface/format.go`,
`jq '.surface_version,(.tools|length)' internal/mcp/tool_surface.golden.json`).
The tag scheme is ADR-011 `v<MCPSurfaceVersion>.<RequiredDataFormat>.<build>`.

## What it does

An orphaned transcript archive (a valid `.jsonl.zst` whose manifest was never
written) can be repaired by one command, on CLI and MCP. The manifest is
regenerated for the EXISTING archive: hash and sizes are recomputed, the zst is
never rewritten, `--adapter` and `--captured-at` are required operator claims
(`captured_at` is stored in UTC), and the manifest carries a `regenerated`
marker naming the basis of each non-byte-derived field. Archives younger than the
tidy grace are refused; an existing manifest is never overwritten.

## Rollout rule (read this first)

**Do not run `vp archive repair-manifest` / `vp_archive_repair_manifest` until
every host, hooks included, runs v11 or later.** An older binary's link path
rewrites the manifest through a struct without `regenerated` and silently drops
it; a hook on an older binary warns on a newer surface stamp and continues. The
surface version moved 10 to 11 so that MCP hosts on v10 are refused after the
first v11 write. Hooks are not refused, so the rule above is operational, not enforced.
See the ADR-001 amendment of 2026-11-20.

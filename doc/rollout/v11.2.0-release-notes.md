## Upgrade and rollout (read this first)

### 1. Do not run `repair-manifest` until every host, hooks included, is on v11

**Do not run `vp archive repair-manifest` / `vp_archive_repair_manifest` until
every host runs v11 or later.** An older binary's link path rewrites the manifest
through a struct without `regenerated` and silently drops it. The surface version
moved 10 to 11 so that an MCP host still on v10 is refused after the first v11
write, but a v10 **hook** only warns on a newer surface stamp and carries on, so
for hooks this rule is operational, not enforced. See the ADR-001 amendment of
2026-11-20.

### 2. Any host that signs archives must run v11 to `sync` (SG1A: a tidy behaviour change)

`vp vault tidy` / `sync` now sweep a transcript manifest's detached signature
(`<name>.manifest.json.sig`) together with its manifest. Before this, a new `.sig`
was **Reported** dirt, and Reported dirt blocks every `vp vault sync`.

- A host still on **v10 keeps reporting `.sig` as blocking dirt.** On a vault that
  has signed manifests, a v10 host cannot sync them; run v11 on every host that
  signs archives (and on any host that syncs a vault they write to).
- An **orphan** `.sig` (no manifest beside it) stays Reported on purpose: a live
  orphan signature needs a human. So does a `.sig` anywhere other than directly
  under `Projects/<p>/transcripts/`. An unmerged (`DU`/`UD`) `.sig` status is a
  merge conflict, not a deletion, and still runs the orphan guard; a plain
  deletion of a manifest and its `.sig` is swept.
- `<manifest>.<tag>.sig.bak` and `.bak` files stay covered by the canonical
  `*.bak` gitignore and never reach tidy.
- Accepted window: the manifest is written first, then the new `.sig`. A sweep
  landing between the two can commit a manifest with an absent or stale
  signature; the next sweep commits the `.sig` and heals history. A defer guard
  for this was deliberately refused.

Nothing in this release makes the capture paths (hook, MCP, Codex) sign. Only an
archive that is **already signed** is kept signed.

### 3. Renaming a signed project needs a key that signs non-interactively (SG1B)

`vp vault rename`, `vp_vault_rename` and `vp_vault_copy_as` on a project whose
transcript manifests are signed now **re-sign every rewritten manifest** instead of
refusing. (In the commits between the tags the rename refused such a project; that
refusal is gone.)

- Before any write (so under `--dry-run` and the MCP `plan` too) the rename proves
  signing works with a real throwaway sign and verify, in the system temp
  directory, never inside the vault. **One ~10 s deadline covers the sign and the
  verify together**, not 10 s each. A key that cannot sign is a plan refusal and
  nothing is written.
- **A passphrase-protected key with no agent is refused at plan time. This is a
  documented limitation of this release.** The rename signs with no stdin, no
  controlling terminal, no askpass and no pinentry (gpg runs with
  `--pinentry-mode error`, so an encrypted gpg key is refused the same way as an
  encrypted ssh key, and this is covered by a test). A key held by a running agent
  that needs no prompt works; an unencrypted key works. An agent-backed path is
  Stage 2, not in this release.
- A failure part-way through rolls the whole rename back byte for byte (the old
  project is restored from `HEAD`, the new one removed), `.sig` files included.
- **Also fixed: a pre-existing rename defect.** A failure between the rename
  commit and the lifecycle marker recording it (a marker-write error included)
  used to leave the rename committed while returning an error. It now rolls back
  to the parent. This affects every rename, signed or not.
- A capture writing into the moving tree mid-rename races exactly as it did
  before; the signed rename does not change that.
- Windows: the no-console signing launch is compile-checked only; Windows CI does
  not run the signing tests.

Detail: `doc/VAULT-LIFECYCLE.md` ("A signed project is re-signed") and the ADR-001
amendment.

## What it does

### Repairing an orphaned transcript (`912dfbc`)

An archive whose capture died between writing `<name>.jsonl.zst` and
`<name>.manifest.json` is an orphan. `vp archive repair-manifest` (CLI) and
`vp_archive_repair_manifest` (MCP; `dry_run:true` is read-only) regenerate a true
manifest for the **existing** archive and never rewrite the `.zst`.

- Listing first, then apply one; there is no bulk mode, and the listing prints each
  exact command.
- Apply requires `--adapter` and `--captured-at`; both are operator claims
  (`captured_at` is stored in UTC). The listing's mtime and filename day are hints
  only.
- Hash and sizes (`source_sha256`, `source_bytes`, `compressed_bytes`), `model` and
  `turn_count` are derived from the archive bytes. `session_id` and `project_slug`
  come from the name and path. `git_head`, `captured_by_hostname`, `vp_version` and
  the session-note link are not recoverable and are left empty.
- A new optional `regenerated` object records when, by which host and version, and
  the basis of every non-byte-derived field.
- Refuses an archive younger than the 10-minute pair grace, refuses an orphan that
  already has a `.sig`, and never overwrites an existing manifest. It takes the
  same manifest lock as `archive create`.

### A crashed capture no longer blocks push, and is reported (`9970720`, `1a54ca4`)

A lone `.jsonl.zst` older than the pair grace used to be deferred forever and, via
the direct push path, could block the push of everything already committed. It is
now classified **Orphaned**: never swept, never committed, never blocking, and
reported by tidy, sync and the MCP surface (the bootstrap alert too). `vp vault
status` (CLI and `vp_vault_status`) no longer prints "Working tree: clean" for a
tree whose only dirt is an orphaned, deferred or left-departed entry (status
report version 3 to 4; no tool-schema change). The repair for an orphan is the
command above.

### Signed manifests stay coherent (`c61ce6b`, with SG1A and SG1B above)

A manifest rewrite never leaves a stale signature. One helper owns every manifest
write and re-signs **only a manifest that already has a `.sig`**; signedness is
maintained, never upgraded. Linking a session note first checks the signing key is
usable and refuses (changing nothing) if not; a failed re-sign restores the prior
manifest and `.sig` byte for byte. `archive create` over a changed source always
leaves a coherent new pair and moves the previous manifest and signature to
`.bak` names. This only changes behaviour for operators who sign: no capture path
signs today.

### `vp init` names the vault it resolved (`0392c27`)

`vp init` resolves the project vault once, prints `vp init: project vault = <path>
(source: <source>)` to stderr before scaffolding, and drops the unchecked "Vault:
already configured" line. An inert `--no-git` on an existing config now gets an
explicit `[skip]` row. This closes the 2026-11-03 incident in which hand-run
`vp init` from throwaway directories scaffolded projects into the live vault with
nothing naming it.

## Changes in tooling and tests only

No effect on a released binary's behaviour unless stated.

- **Under-test tripwire, completed** (`f765d24`, `84f47a9`): no test can create
  `.vp-locks/`, a project directory or any directory in the operator's configured
  vault before the tripwire fires. One chokepoint per primitive; a new
  `vault-dir-creation` source-audit rule covers every raw directory creator.
  `archive.Create`'s transcripts directory now goes through `EnsureVaultDir`,
  reversing the 2026-08-20 ruling that it never would (production-visible only as
  the same refusals with the same text).
- **Source audit follows paths through helpers** (`82cfbbc`): the
  `vault-write-outside-funnel` rule is now type-based and follows a vault path
  through producers, wrappers and typed sources. It found real raw writes; each is
  a baselined entry with a stated reason.
- **Imports ledger written through the locked funnel** (`12ec086`): the host-local
  `imported-sessions.jsonl` is appended under the per-path lock. One real defect
  fixed: two overlapping `vp migrate` runs could both move the legacy ledger,
  duplicating lines and aborting the second with `ENOENT`. The ledger is a hint
  only, so no import was ever skipped.
- **Test fixes**: `TestCaptureIsUnaffectedByTranscriptExclusion` compared
  clock-dependent fields and failed intermittently; the test is fixed, not
  production (`32cd894`). The `AcquirePair` second-leg test and an ambient-alias
  fixture are portable to Windows (`82274f4`).
- **CI**: signing tests fail rather than skip under CI when `ssh-keygen` / `gpg`
  are missing, and the test job installs them (`c61ce6b`).
